Oprócz typów wbudowanych (String, Int, boolean...) FunnyGuilds ma kilka
własnych typów wartości konfiguracyjnych. Ta strona zbiera je wszystkie razem
z możliwymi wartościami i przykładami. Opis konkretnej opcji znajduje się na
stronie funkcji, której dotyczy (np. [Gildie](/guilds/) czy
[Tereny i ochrona](/territories/)).

## Ochrona tożsamości graczy

Kontrola konfliktów przy starcie jest opcjonalna i domyślnie wyłączona.
W `config.yml` można ją włączyć przez:

```yaml
prevent-uuid-conflicts: true # domyślnie: false
```

Włączona kontrola szuka identycznego nicku zapisanego z różnymi UUID w plikach
YAML lub bazie SQL, zanim wczyta graczy i gildie. Wielkość liter ma znaczenie:
`Steve` i `steve` mogą być osobnymi kontami na serwerze offline-mode.
Konflikt przerywa uruchamianie FunnyGuilds bez wpływu na start reszty serwera.
Plugin nie scala ani nie usuwa automatycznie kont i nie zapisuje częściowo
wczytanych danych. Przy włączonej kontroli nieczytelne pliki YAML lub brakujące
dane tożsamości w YAML również zatrzymują ładowanie z krótkim podsumowaniem.
Przy wyłączonej kontroli nieczytelne pliki YAML są pomijane z podsumowaniem błędów.

Ta opcja nie blokuje logowania, tworzenia kont ani zmian nicku. Inne konto może
użyć dawnego nicku gracza, który zmienił nazwę poza serwerem. Ponieważ oba konta
mogą pozostać zapisane pod identyczną nazwą aż do ponownego wejścia poprzedniego
właściciela, włączona kontrola może zatrzymać kolejny start. Na serwerach, gdzie
taki stan jest prawidłowy, pozostaw `prevent-uuid-conflicts: false`.
FunnyGuilds nie zastępuje pluginu uwierzytelniającego ani jego zasad dotyczących nicków.

Sposób bezpiecznego rozstrzygnięcia konfliktu opisuje [FAQ](/faq/#konflikt-nicku-i-uuid).

## Regex

Typ używany do walidacji Stringów — nazw, tagów itd.

Predefiniowane wartości:

| Wartość                      | Opis                                                              |
| :---------------------------- | :----------------------------------------------------------------- |
| `LOWERCASE`                  | tylko małe litery                                                  |
| `UPPERCASE`                  | tylko wielkie litery                                               |
| `DIGITS`                     | tylko cyfry                                                        |
| `LOWERCASE_DIGITS`           | małe litery i cyfry                                                |
| `UPPERCASE_DIGITS`           | wielkie litery i cyfry                                             |
| `LETTERS`                    | małe i wielkie litery                                              |
| `LETTERS_DIGITS`             | małe i wielkie litery oraz cyfry                                   |
| `LETTERS_DIGITS_UNDERSCORE`  | małe i wielkie litery, cyfry oraz podkreślnik                      |

Dla tego typu można też podać własne wyrażenie regularne (do jego
przetestowania służy np. [regex101](https://regex101.com/)).

## Duration

Format: `<wartość><jednostka><wartość><jednostka><...>`

Jednostki:
- `s` — sekundy
- `m` — minuty
- `h` — godziny
- `d` — dni

Przykład: `1m30s` — 1,5 minuty.

## Material

Nazwa materiału Bukkita (bloku lub przedmiotu), np. `DIAMOND` lub
`ender_crystal` — wielkość liter nie ma znaczenia. Pełna lista nazw
znajduje się w [dokumentacji `org.bukkit.Material`](https://spigotdocs.okaeri.cloud/select/org/bukkit/Material.html).

## ItemStack

Format: `<ilość> <MATERIAL>[:<data>] [atrybut:wartość] [atrybut:wartość] ...`

Atrybuty (wszystkie opcjonalne, w dowolnej kolejności):

| Atrybut | Wartość | Opis |
|---|---|---|
| `name` / `displayname` | tekst | Nazwa przedmiotu (kolory `&`, `_` zamienia się na spację) |
| `lore` | `linia1#linia2#...` | Opis przedmiotu, linie oddzielone `#` |
| `enchant` / `enchantment` | `ZAKLĘCIE:poziom` | Pojedyncze zaklęcie |
| `enchants` / `enchantments` | `E1:l1,E2:l2` | Kilka zaklęć naraz |
| `skullowner` | nick | Właściciel czaszki gracza |
| `flags` / `itemflags` | `FLAGA1,FLAGA2` | Flagi przedmiotu (`ItemFlag`) |
| `armorcolor` | `r_g_b` | Kolor skórzanej zbroi |

Przykład: `1 diamond name:&bNagroda_za_pierwsza_gildie_na_serwerze` — utworzy
diament o nazwie „Nagroda za pierwsza gildie na serwerze”.

Nazwy i lore przedmiotów domyślnie nie są pisane kursywą. Dotyczy to także
definicji w `guild-item-library` w pliku `items.yml` oraz tekstów przedmiotów
w GUI. Kursywę można włączyć jawnie, np. `<italic>Złoty klucz</italic>`.

## Requirements

```yaml
# priority: <wartość> (od 0 do 127) # 1*
items: (/configuration/#itemstack)
- <przedmiot 1>
- <przedmiot 2>
- ...
exp: <wartość>
money: <wartość> (wymagany plugin Vault)
# ranking: <wartość> # 2*
```

1\* — priorytet należy podać tylko wtedy, gdy wymagania zależą od
posiadanych uprawnień.

2\* — wartość rankingu należy podać tylko tam, gdzie ma ona zastosowanie —
np. przy zakładaniu gildii lub dołączaniu do niej.
