A list of the most frequently asked questions about the FunnyGuilds plugin.

## Username and UUID conflicts

`CRITICAL USER IDENTITY CONFLICT` means the stored data contains two different
UUIDs for one username. Comparison is case insensitive. The console lists both
UUIDs and their sources (file paths or the SQL table). FunnyGuilds aborts on the
first conflict, before loading users and guilds or starting automatic saves.
Account records are not automatically deleted or merged.

1. Stop the server and back up FunnyGuilds data, including the SQL database if used.
2. Check authentication and UUID forwarding settings in Velocity/Bungee.
   A proxy backend can legitimately use `online-mode=false`; check the whole
   network configuration before changing that setting.
3. Identify the accounts belonging to the reported UUIDs. Possible causes include
   authentication changes, imported data and another account reusing a username.
4. Resolve the conflict manually, accounting for player data and guild references,
   then restart the server. Do not delete all user data.

If a conflict occurs during login, only that player is rejected. Customize their
message with `loginUuidConflict` in the
[language file](/en/configuration/#player-identity-protection).
A new owner of an old username may need manual resolution while the previous
account is still stored under that name. Normal username changes for the same
UUID to an available name continue to work.

Separate errors `Invalid or missing UUID`, `Missing or blank username`,
`Could not read user file` and `Multiple usernames for UUID` indicate an invalid
UUID, missing username, unreadable file or different stored usernames for one
UUID, respectively. These also require checking the data before restarting.

## Fog when entering or leaving a guild's territory

In `config.yml`, change

```yaml
notification-boss-bar-flags:
- CREATE_FOG
```

to

```yaml
notification-boss-bar-flags: []
```

## What is a nightly build and where can I download one?

Nightly builds are plugin builds containing all the latest changes to the source code. An official release is put together every few nightly builds. Individual builds are available here: [FunnyGuilds Nightly](https://ci.insertt.dev/job/FunnyGuilds/).

After installing such a version, you'll keep seeing a message about a newer version being available. This happens because the updater only takes official releases into account — nightlies aren't included. The message can be ignored.

## Tags, scoreboards and points under the nickname aren't working

The most common cause of this kind of issue is another plugin using scoreboards and the elements tied to them, such as team tags above players' heads or points under the nickname. Since Bukkit provides no sensible API for this, every plugin registers its own scoreboards, which is often a source of conflicts. One example is Scoreboard Stats, which offers a `compatibility mode` option that lets the two work together correctly. If a plugin has no similar option in its configuration, it's incompatible with FunnyGuilds.

## How do I integrate the plugin with CombatLogX?

CombatLogX does not kill players with administrator/`op` permissions, so the integration cannot be tested on such an account. CombatLogX may also override the death message set in FunnyGuilds.
