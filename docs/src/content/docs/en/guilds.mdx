## Creating a guild

A guild is created with the `/zaloz <tag> <name>` command. The command marks
out the guild's territory and places a heart on it:

<GuildCreationDemo
  label="DZK"
  command="/zaloz DZK dzikoysk"
  phaseLabels={['Unclaimed land', 'Running the command', 'Territory claimed']}
/>

The requirements for creating one are configured separately, in `items.yml` —
by default a set of items, an XP level, a ranking score and (optionally) a
Vault balance:

| Requirement | Default |
|---|---|
| Items | 64 diamonds, 64 emeralds, 64 iron ingots |
| XP level | 30 |
| Ranking | 1000 |
| Balance (Vault) | 10,000 |

You can define several such sets at once — each tied to a different
permission and sorted by priority, so the first set the player has permission
for is the one that applies. The default configuration also includes a `vip`
set (permission `funnyguilds.items.vip`) with half the cost, lower level and
ranking requirements and no balance requirement. A player with the
`funnyguilds.items.admin.bypass` permission skips every requirement.

By default, `/przedmioty` opens a GUI with all items required to create a
guild. Click “Pokaż wszystkie” (“Show all”) to display only missing items. Click again to
restore the full list.

Names and lore from `guild-item-library`, as well as GUI item text, are
non-italic by default. To enable italics, use the MiniMessage `<italic>` tag
in the relevant text.

Item requirements compare only the properties supplied in
[`guild-item-library`](/en/configuration/#guild-item-definitions-itemsyml).
All properties are optional, including material, so a requirement can match
only a name regardless of item type. Unconfigured metadata is ignored.

Payment combines matching stacks even when their types or other metadata differ.
Only the main inventory and hotbar count; armor and offhand slots are excluded.
Ender chest counts in the GUI are informational. Each item pays for one
requirement only: overlapping definitions need enough separate items to cover
their combined quantities. Items are allocated across requirements before
payment, and only the exact required quantities are removed. For overlapping
definitions, GUI inventory counts exclude items reserved for other requirements.

Before payment, every affected inventory slot is checked again against its
allocated requirements and quantity. If a slot no longer qualifies, creation
stops before any items or money are taken. Valid items are reserved before the
Vault withdrawal. If withdrawal fails, the exact reserved items are returned;
any that no longer fit in the inventory are dropped at the player's feet.

The guild's name and tag are validated separately:

| Option | Default | Description |
|---|---|---|
| `name-length` / `name-min-length` | 22 / 4 | Guild name length |
| `tag-length` / `tag-min-length` | 4 / 2 | Guild tag length |
| `name-regex` / `tag-regex` | `LETTERS` | Allowed characters (see the [Regex type](/en/configuration/#regex)) |
| `guild-tag-keep-case` | `true` | Keeps the tag's case as typed at creation |
| `guild-tag-uppercase` | `false` | Forces uppercase tags (when `keep-case` is off) |
| `check-for-restricted-guild-names` | `false` | Enables the `restricted-guild-names`/`restricted-guild-tags` list |
| `whitelist` | `false` | Flips the list above from a blacklist into a whitelist |

A new guild's territory also has to sit far enough from spawn and other
players — this is controlled by `create-distance`,
`create-guild-min-distance` and `blocked-worlds`, described in more detail in
[Territories & protection](/en/territories/).

A guild can have at most `max-members` players (**15** by default).

:::tip[Inviting by radius]
`/zapros *` instantly invites everyone within a radius
(`invite-command-all-default-range`, 10 blocks by default, up to
`invite-command-all-max-range` — 50 blocks).
:::

## Guild panel

`/panel` shows the leader, deputies, online member count, rank, points, lives,
expiry, territory level and radius, and PvP settings for the guild and its
alliances. The teleport button uses the same permissions and rules as
`/baza`, including the cost, delay, and VIP permissions. Use `/ustawbaze` to
set the destination.

### Guild roles

Open **Roles and permissions** in `/panel`. After clicking **Create role**,
the leader has 30 seconds to enter the name in chat. The message goes only
to the editor. Type `cancel` to return to the role list. Assign the role from
the player-head list, which includes offline members. The leader role is read-only.

Click a permission to cycle through **Inherit**, **Allow**, and **Deny**.
Individual overrides take priority. Custom roles inherit missing settings
from the member role. The panel shows each decision and its source.
Deleting a role moves its members back to the member role. Settings survive restarts.

In **Members**, invite an online player from the player-head list or revoke
a sent invitation under **Pending invitations**. Select a member to kick
them after confirmation. The panel uses the same permissions as `/zapros`
and `/wyrzuc`.

### Guild activity log

Open **Guild activity log** in `/panel`. Each entry shows the time, actor, and
description. Newest entries appear first. Click the filter to switch
categories and use the arrows to change pages. The log covers invitations,
membership, permissions, PvP, alliances, wars, upgrades, and renewals. It also
shows purchase costs. The leader can grant **View activity log** to others.

## Guild validity

A newly created guild starts with `validity-start` worth of validity
(**14 days** by default) — once it runs out, the guild is deleted
automatically.

Renew through `/panel` or `/przedluz [period]`. The panel shows the final
cost, any shortfall, and the new expiry date before confirmation. Purchased
time is added to the current expiry date. With no argument, the command buys
`validity-time` (14 days for 10 diamonds by default). The panel defaults to
12 hours and 1, 3, 5, 7, 14, and 31 days. Change the options with
`validity-periods`.

The default `validity-when: 0` allows renewals at any time, including
consecutive purchases. A positive value such as `14d` limits renewal to
the last 14 days of the guild's validity.
See [configuration](/en/configuration/#guild-purchases) for rates and payment modes.

## Disbanding a guild

Disbanding takes two steps: `/usun` starts it and `/potwierdz` confirms it.
`guild-delete-cancel-if-someone-is-on-region` blocks disbanding while
someone from outside the guild is standing on its territory.

:::note[Other options]
- `should-give-rewards-for-first-guild` / `rewards-for-first-guild` — a reward
  for the first guild ever created on the server.
- `rank-reset-needed-items` / `stats-reset-needed-items` — the cost of
  `/rankreset` and `/statsreset`, see [Rankings & combat](/en/rankings-combat/).
- `player-lookup-ignorecase` — whether looking up players by name ignores case.
:::
