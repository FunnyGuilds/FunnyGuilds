### FunnyGuilds

The plugin's main instance. It should be fetched only once, e.g.:

```java
public class MyPlugin extends JavaPlugin {

    private FunnyGuilds funnyGuilds;
    
    @Override
    public void onEnable() {
        funnyGuilds = FunnyGuilds.getInstance();
    }
    
}
```

### User

Available methods for fetching a user:

- `UserManager#findByName(String)`
- `UserManager#findByPlayer(Player)`
- `UserManager#findByUuid(UUID)`

Example usage:

```java
UserManager userManager = funnyGuilds.getUserManager();
Optional<User> userOption = userManager.findByName("PlayerName");

if (userOption.isPresent()) {
    User user = userOption.orElseThrow();
}
```

`UserManager#addUser(User)` rejects a different user instance with an already
registered UUID by throwing `IllegalStateException`. The existing user instance
and both indexes remain unchanged. After rejection, do not use the supplied
instance as a registered user; retrieve the existing account with `findByUuid(UUID)`.

### Guild

Available methods for fetching a guild:

- `GuildManager#findByName(String)`
- `GuildManager#findByTag(String)`
- `GuildManager#findByUuid(UUID)`
- `User#getGuild()`

Guild member, deputy, ally, enemy, and allied PvP collections are read-only.
Use `Guild` methods such as `addMember` and `removeAlly` to make changes that
will be picked up by persistence. `Guild#getHome()` and
`Region#getCenter()` return copies of their locations.

Example usage:

```java
GuildManager guildManager = funnyGuilds.getGuildManager();
Optional<Guild> guildOption = guildManager.findByTag("TAG");

if (guildOption.isPresent()) {
    Guild guild = guildOption.orElseThrow();
}
```

```java
Optional<Guild> guildOption = user.getGuild();

if (guildOption.isPresent()) {
    Guild guild = guildOption.orElseThrow();
}
```

### Guild roles and permissions

- `FunnyGuilds#getGuildPermissionChecker()` exposes
  `getStoredDecision(guild, user, permission)` with the stored value and source.
  `handlePermission` and `handleProtectionPermission` also include permission
  events from integrations when an action runs.
- `FunnyGuilds#getGuildRoleService()` creates and assigns roles and edits
  permissions, overrides, and delegation scope. Run mutations on the main
  server thread and supply the actor to check. `GuildRoleChangeEvent` exposes
  the policy before and after a committed change.

### Extension commands

Modules in `extensions/` can contribute commands at startup through
`ExtensionCommands` from `:extensions:api`. The module supplies a stable
`module-name.command-name` ID, default name, aliases, and an instance of a class with
`@FunnyComponent` and `@FunnyCommand` annotations. The command annotation
uses `${extension.<id>.name}` and `${extension.<id>.aliases}` and declares the
Bukkit permission.

Wire a new module into the `:plugin` bootstrap, which passes the registry to
the module's `registerCommands` method. The module creates each command
instance with its dependencies. The shared configuration installs these commands
on server startup. The panel uses this path for `guild-panel.panel`. Use
`FunnyGuilds#getPanelModule().open(player)` to open the GUI on the main server
thread. Callers are responsible for checking access at their own entry point.

### Items and requirements

The `items.yml` configuration is available straight from the plugin instance:

- `FunnyGuilds#getItemsConfiguration()` — the item library and requirement sets.
- `FunnyGuilds#getGuildItemSetService()` — the set a given player qualifies for.
- `FunnyGuilds#getGuildItemRequirementChecker()` — whether a player meets the requirements.

### Listening for events

#### Guild territory transitions

`GuildPreRegionTransitionEvent` is synchronous. Listeners can cancel it before
movement or teleport handling completes. `getFromGuild()` and `getToGuild()`
return `Optional<Guild>`. An empty value represents a location outside guild
territory. Moving directly between two guilds fires one event. Cancellation
blocks the entire transition, including entry and exit notifications.

FunnyGuilds checks the destination at Bukkit's `HIGHEST` priority. Integrations
that change the destination should do so at an earlier priority. Notifications
use the final destination observed at `MONITOR`.

`GuildRegionLeaveEvent` and `GuildRegionEnterEvent` remain asynchronous.
An accepted transition between guilds fires the leave event before the enter
event in the same task. Treat these as notifications. Integrations that used
`setCancelled(true)` on them should move their veto to
`GuildPreRegionTransitionEvent`.

Events related to:
- Ranking changes: [net/dzikoysk/funnyguilds/event/rank](https://github.com/FunnyGuilds/FunnyGuilds/tree/5.x/plugin/src/main/java/net/dzikoysk/funnyguilds/event/rank)
- Guilds: [net/dzikoysk/funnyguilds/event/guild](https://github.com/FunnyGuilds/FunnyGuilds/tree/5.x/plugin/src/main/java/net/dzikoysk/funnyguilds/event/guild)
- Guild members: [net/dzikoysk/funnyguilds/event/guild/member](https://github.com/FunnyGuilds/FunnyGuilds/tree/5.x/plugin/src/main/java/net/dzikoysk/funnyguilds/event/guild/member)
- Alliances: [net/dzikoysk/funnyguilds/event/guild/ally](https://github.com/FunnyGuilds/FunnyGuilds/tree/5.x/plugin/src/main/java/net/dzikoysk/funnyguilds/event/guild/ally)

An example using `GuildDeleteEvent`:

```java
public class GuildDeleteListener implements Listener {

    @EventHandler
    public void onGuildDelete(GuildDeleteEvent event) {
        Guild guild = event.getGuild();
        User doer = event.getDoer();
        FunnyEvent.EventCause eventCause = event.getEventCause();

    }
    
}
```

Registration in the `onEnable()` method:

```java
@Override
public void onEnable() {
    this.getServer().getPluginManager().registerEvents(new GuildDeleteListener(), this);
}
```
